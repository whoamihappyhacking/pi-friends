# Pi Friends · 派的伙伴

一个小工具、一块常驻面板，让几位有名字的小伙伴并行帮你干活。

## 日常使用

直接在 Pi 中说：

> 派两位小伙伴，一位调整导航，一位修复表单。使用必点 AI，分别用 glm-5.3-flash 和 qwen3.8-flash。不要改同一个文件，改完告诉我验证结果。

> 看看大家的进度；平时只更新上方面板，最后统一告诉我。

> 告诉胡歌，注意保留键盘导航。

> 胡歌做完之后，再让他处理侧栏。

> 周迅这项任务改成静默，完成再通知。

> 停止一凡的任务。

> 验收通过，让胡歌离开。

> 验收失败，让他离开，保留失败原因。

> 让周迅离开。

成员完成后先待验收。主 Agent 实际检查后调用 accept 或 reject，插件自动离队；不会从一段聊天文字猜测验收结论。主动遣散用 dismiss，也可在 `/f` 选择验收通过、验收失败或请他离开。

离队成员从常驻面板、默认列表和 `/f` 菜单移除，正在运行的进程终止，待处理消息取消。修改文件、完整结果、会话及离开原因保留，list 的 history=true 或指定原 ID 可查。离开后不再接受续派，应派新成员；stop 只是停止，仍保留在队以便继续。模型调用失败本身仍显示“失败”等待主 Agent 处理，不会冒充“验收失败”。

面板默认出现在输入框上方，显示名字、状态、一句话进度和距离上次阶段汇报的秒数。超过一分钟没有新汇报时，插件最多放入一条待处理的进度请求；请求在当前工具结束后的安全时机被读取。模型/工具正在等待时不会伪造进度。

状态在面板和菜单列表中只显示 emoji：⏳ 排队、🚀 启动、⚙️ 工作、🔄 重试、🙋 需要帮助、⚠️ 进度待确认、📋 待验收、❌ 失败、⏹️ 停止、⏸️ 中断、👋 离开；🔕 表示静默。文字释义仅在此说明中展示。

插件在派发时立即分配人名，不依赖模型记住命名要求。已离队成员不再占用名字，新成员可复用；候选池用完后生成普通人名，不再使用“伙伴1、伙伴2”编号。历史同名成员仍以内部 UUID 区分，直接按人名操作时优先匹配当前在队成员。

无需记命令。可选 `/f` 打开列表，选人后查看详情、补充要求、追加任务、切换静默或停止。当前菜单是键盘选择，不需要填写 JSON；不占用 Pi 自带快捷键。详情是只读意义的快照：编辑详情窗口内的文本不会发给小伙伴。

名字只是昵称：启动时随机给一个不重名的人名，小伙伴可自己另选；同一会话续派保留名字。内部 UUID 才是真实身份，名字不固定绑定技能、任务或模型。

## 能力与边界

- 每位小伙伴是独立 Pi RPC 子进程；只显式加载本包的 `worker.ts`，禁用其它扩展发现与提示词模板，绝不调用旧 `pi-subagents`。技能默认关闭，可设置 skills=true 允许 Pi 发现技能。
- 默认最多 4 个子进程，最多 16 个未完成任务，超额排队。主 Agent 继续工作，子代理结果异步返回。
- 每分钟标记进度更新，面板每秒刷新；普通进度不主动唤醒空闲主模型，只把紧凑状态作为隐藏上下文提供给它，不在对话中产生表格或消息块，也不积累过期快照。完成、失败、阻塞、模型切换会唤醒主 Agent 收尾；主 Agent 已通过 list/wait 收到的结果不再重复推送。
- 派出伙伴后，主 Agent 在每次模型调用中都会收到隐藏的收尾规则：除非用户明确要求后台继续，最终回复前应先等待伙伴、检查交付、验收或处理异常，再只向用户发送一次合并总结。该规则在 spawn 后的同一轮也生效。
- friends 工具调用使用无边框的一行提示；成功结果不另铺大块内容，详细数据只进入主 Agent 上下文。错误保留一行提示。常驻面板仍是用户观察状态的主要位置。
- 静默任务不发定时进度、不催报，但面板仍可观察，完成/失败/需要帮助仍通知。
- `send` 默认排下一项任务，`steer` 才在工具结束后干预当前任务；消息分别记录 pending / delivered / read / rejected / cancelled。read 表示进入子代理会话，不保证模型已经正确执行了要求。
- 结果保存为待主 Agent 验收；主 Agent 应检查组合后的效果。没有自动保证“所有检查已通过”。
- 默认连续三次工具错误或单次任务超过 30 分钟会停止并保留修改；均可配置，长任务可单独覆盖超时。不把不断输出工具日志当成实际进展。
- 每人保留自己的 Pi 会话和简短任务上下文。跟进任务复用会话，Pi 自身处理自动上下文压缩。不会默认复制主 Agent 的全部聊天历史。
- `/reload` 或正常退出时，运行中任务停止并记为“已中断”；恢复同一个主会话后可用同一名字继续。不会假装从某一条 shell 指令的中间自动断点续跑。新建一个无关的主会话不会自动接管旧团队。
- 意外崩溃后再次打开原团队，会检查之前记录的子进程身份并停止遗留进程，然后标为中断。此清理在 Linux 上实现；文件、会话和最后进度保留。

## Provider 和模型

插件不内置任何 Provider 或模型名。选择顺序为：派发时显式指定的 provider/model → 本机配置 → 主会话当前模型。显式选择时必须同时提供 provider 和 model，防止把两个来源拼成无效组合。`friends models` 默认列出全部可用模型，也可按 Provider 筛选。

thinking 优先使用显式参数，其次 `modelDefaults[provider][model].thinking`；使用配置默认模型时也可设置顶层 thinking。均未设置则交给 Pi 处理。插件不覆盖显式档位，也不内置厂商兼容分支。下面是当前这台机器的个人配置，不是插件代码中的默认值。

插件本身不硬编码启用备用模型。默认配置位于 `~/.pi/agent/friends/config.json`：

```json
{
  "provider": "openai-codex",
  "model": "gpt-5.6-sol",
  "fast": true,
  "modelDefaults": {
    "openai-codex": {
      "gpt-5.6-sol": { "thinking": "xhigh", "fast": true }
    }
  },
  "maxConcurrent": 4,
  "progressMs": 60000,
  "stallMs": 180000,
  "timeoutMs": 1800000
}
```

当前未配置自动备用模型。需要时可另加 `fallback`；fromProvider 可限定哪些来源允许切换，省略则适用于任何来源，目标 Provider、模型及档位均由配置提供。模型需在 Pi 中已配置且可用。登录和 API 凭据由 Pi 管理，本插件不复制凭据。

## 可配置的运行策略

以下字段均放在本机 friends/config.json；省略时使用表中默认值，非法值报错，不暗中改值。

| 字段 | 默认 | 含义 |
|---|---|---|
| maxConcurrent | 4 | 并发进程数，正整数，无隐藏的 8 人上限 |
| maxTasks | 16 | 新派发时的未完成任务额度，0 不限制 |
| maxToolFailures | 3 | 连续工具错误停止阈值，0 禁用自动停止 |
| timeoutMs | 1800000 | 每轮任务超时，0 不限时；spawn 可单独指定，后续续派沿用成员设置 |
| progressMs | 60000 | 进度通知间隔，正整数毫秒；实际检查粒度约 1 秒 |
| stallMs | 180000 | 无阶段进度提醒间隔，0 禁用 |
| namePool | 内置示例人名 | 可替换候选池；空数组或候选占用时自动生成普通人名，不使用编号 |
| skills | false | 是否允许子代理发现 Pi 技能 |

friend_exec 的 timeout 默认 60 秒，可按命令指定更长时间，不再限制为 120 秒。协作规则仍要求声明写入路径，命令工具可执行任务需要的操作，不限于测试。

保留的固定值用于协议和展示：每秒检查、单次 wait 最长 30 秒、面板最多 8 行、结果推送摘要限长、文件变更保留最近 30 条及成员结果索引最近 10 条。最新完整结果、消息确认记录和 Pi 会话保留；界面摘要不是完整记录。运行时仍仅加载本插件的子代理工具，不自动加载其它扩展或递归派代理。

## 文件协作机制

主 Agent 和小伙伴的 read/edit/write 都有文件占用检查。现有文件必须先 read，写入前检查内容 SHA-256；读后发生变化时拒绝旧快照写入，重新读取后才能再改。符号链接按真实路径协调。共享记录包含修改人、时间、摘要、前后指纹，保留最近 30 次变更。

文件锁覆盖一次工具操作，避免同一时刻覆盖；它不是长期的任务分工预留。主 Agent 仍应按文件拆任务。子代理的 `friend_exec` 用于测试命令，必须声明预计写入的 `writePaths`；工具为声明的文件加锁并记录变化。

**这是一套可信 Agent 之间的协作机制，不是操作系统沙箱。** shell 命令可以产生未声明的写入，外部编辑器也不会遵守锁；这些情况无法保证拦截。两个代理写不同文件造成的逻辑冲突同样需要主 Agent 验收。

## 安装与开发

```bash
pi install https://github.com/whoamihappyhacking/pi-friends
```

本机开发目录也可以直接安装：`pi install /path/to/pi-friends`。

不要同时启用旧的子代理插件。旧包和历史数据可以保留，只从 Pi 的启用配置里移除旧包。已有 Pi 窗口使用 `/reload` 加载修改；新窗口直接生效。

状态默认保存在 `~/.pi/agent/friends/`。`PI_FRIENDS_HOME` 可覆盖状态位置，测试用它隔离数据。

```bash
npm test
# 同一 Pi 进程更新重载、菜单与工具遣散回归，不调用模型：
node test/reload-live.mjs
# 以下是真实模型调用，会使用账户额度：
node test/live.mjs
node test/parent-live.mjs
```

`test/live.mjs` 派四位子代理修改导航、表单、弹窗和移动端 CSS，并验证静默、文件记录和继续会话。`test/parent-live.mjs` 让真实主模型调用本包的 friends 工具派出两人，检查算术修复、结果汇总、TUI widget 事件及旧插件没有参与。

## 工具接口（给主 Agent）

只有 `friends` 一个主工具。action 为 spawn / list / wait / send / stop / quiet / models / model / accept / reject / dismiss。

```json
{"action":"spawn","task":"修复导航","provider":"bai","model":"qwen3.8-flash","context":"只改 nav.css；窄屏不横向溢出"}
{"action":"send","id":"胡歌","message":"注意保留键盘导航","mode":"steer"}
{"action":"send","id":"胡歌","message":"完成后继续侧栏"}
{"action":"accept","id":"胡歌","reason":"检查通过：键盘导航和窄屏布局符合要求"}
{"action":"reject","id":"周迅","reason":"提交结果未满足表单校验要求"}
{"action":"dismiss","id":"一凡","reason":"用户取消任务"}
{"action":"list","history":true}
{"action":"model","id":"胡歌","provider":"openai-codex","model":"gpt-5.6-luna","thinking":"minimal"}
```
